# 🐧 PenguinCraft

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![CI](https://github.com/Volodymyr538/penguincraft/actions/workflows/ci.yml/badge.svg)](https://github.com/Volodymyr538/penguincraft/actions/workflows/ci.yml)
[![Python 3.9+](https://img.shields.io/badge/python-3.9%2B-blue.svg)](https://www.python.org/)
[![Platform: Linux / ChromeOS / Windows](https://img.shields.io/badge/platform-Linux%20%7C%20ChromeOS%20%7C%20Windows-informational.svg)](#установка)

Лёгкий лаунчер Minecraft для Linux, ChromeOS (Crostini) и Windows,
написанный на чистом Python 3 и tkinter — **без сторонних зависимостей**.

Оптимизирован под хромбуки: минимум библиотек, автоматическая загрузка
нужной версии Java, экономные профили JVM, экономия диска за счёт общих
библиотек и ресурсов.

> Пакеты CurseForge напрямую не поддерживаются — используйте версии для
> Modrinth (`.mrpack`) или ставьте моды по одному.

---

## Возможности

- **Версии Minecraft** — полный список Mojang (релизы, снапшоты, старые
  беты и альфы), установка одной кнопкой.
- **Загрузчики модов** — Fabric, Quilt, Forge и NeoForge. Forge/NeoForge
  ставятся официальными installer-jar'ами, как в официальном лаунчере.
- **Аккаунты** — Microsoft (вход по коду устройства), офлайн-профили и
  Ely.by.
- **Моды** — поиск и установка с Modrinth прямо в экземпляр, включение и
  выключение модов, импорт `.jar` из файлов, поиск дубликатов,
  **обновление установленных модов** одной кнопкой и **автоматический
  подбор обязательных зависимостей**.
- **Проверка зависимостей** — поиск модов без нужных библиотек,
  выключенных зависимостей, конфликтов и модов «чужого» загрузчика.
- **Проверка целостности** — сверка файлов игры с манифестом Mojang и
  восстановление повреждённых клиента, библиотек и ресурсов.
- **Автообновление модов** — фоновая проверка обновлений при запуске
  лаунчера с настраиваемым интервалом (игру не блокирует).
- **Ресурспаки и шейдеры** — поиск на Modrinth и установка в
  `resourcepacks/` и `shaderpacks/`. Раньше этот поиск почти всегда был
  пуст — исправлено.
- **Модпаки** — установка `.mrpack` (Modrinth) из файла или по названию,
  с автоматической установкой нужного загрузчика и версии игры, а также
  **обновление сборки** до новой версии «на месте».
- **Экземпляры** — отдельный «домашний» каталог для каждой сборки: свои
  моды, миры, настройки. Ничего не перепутается. Плюс **экспорт и импорт
  экземпляра** архивом и **управление мирами**: экспорт, импорт,
  удаление и резервная копия.
- **Настройки экземпляра** — память, профиль JVM, аргументы, путь к Java,
  разрешение и заметки в отдельном окне.
- **Отчёт о падении** можно посмотреть прямо в лаунчере, а **обновления
  самого лаунчера** проверяются через GitHub Releases.
- **Масштаб интерфейса** 100–200 % для HiDPI-экранов.
- **Оптимизация под хромбуки** — профиль JVM «Хромбук», Serial GC, быстрый
  старт, авто-подбор памяти, программный OpenGL для очень слабых машин.
- **Экономия диска** — библиотеки и ресурсы общие для всех экземпляров,
  одинаковые jar'ы связываются жёсткими ссылками.
- **Диагностика** — команда `doctor` проверяет каталог данных, Java и
  доступ к серверам Mojang и Modrinth.

## Установка

### Windows

Готовые файлы — в разделе [Releases](https://github.com/Volodymyr538/penguincraft/releases):

| Файл | Что это |
|---|---|
| `PenguinCraft-1.4.0-setup.exe` | обычный установщик (права администратора не нужны) |
| `PenguinCraft-1.4.0-portable.exe` | один файл, ничего не устанавливает |

Установщик кладёт лаунчер в `%LOCALAPPDATA%\Programs\PenguinCraft`,
добавляет ярлыки и удаляется штатным образом через «Установка и удаление
программ». Ни Python, ни Java ставить заранее не нужно: Python уже внутри
`.exe`, а Java лаунчер скачает сам.

Данные (библиотеки, ресурсы, экземпляры) живут в
`%LOCALAPPDATA%\PenguinCraft` и при удалении лаунчера сохраняются.

> Собрать `.exe` самостоятельно можно только на Windows — см. раздел
> [Сборка дистрибутивов](#сборка-дистрибутивов).

### Linux / ChromeOS (Crostini)

Нужен **Python 3.9+** и **tkinter** (иногда идёт отдельным пакетом):

```bash
# Debian / Ubuntu / Crostini
sudo apt update
sudo apt install -y python3 python3-tk
```

### Вариант 1 — готовый установщик (рекомендуется для хромбуков)

Один файл, права root не нужны. Ставит лаунчер в домашний каталог и
добавляет пункт в меню «Linux-приложения»:

```bash
sh PenguinCraft-1.4.0-installer.sh              # установить или обновить
sh PenguinCraft-1.4.0-installer.sh --uninstall  # удалить
```

Запуск — из меню ChromeOS (`Linux-приложения` → PenguinCraft) или командой
`~/.local/bin/penguincraft`. Чтобы работала просто `penguincraft`,
добавьте в `~/.profile`:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

Данные игры (`~/.local/share/penguincraft`) при удалении сохраняются.

### Вариант 2 — пакет .deb (системная установка)

```bash
sudo apt install ./penguincraft_1.4.0_all.deb
penguincraft            # или из меню приложений
sudo apt remove penguincraft
```

Пакет сам подтягивает зависимости `python3` и `python3-tk`.

### Вариант 3 — из исходников

```bash
git clone https://github.com/Volodymyr538/penguincraft
cd penguincraft
./run.sh                # графический интерфейс
./run.sh doctor         # проверка окружения
```

Установка через `pip install .` тоже возможна, но менее удобна: код уедет
в `site-packages`, и обновление через `git pull` на него уже не повлияет.

## Сборка дистрибутивов

### Linux / ChromeOS

Готовых файлов нет в репозитории? Соберите их сами — нужен только
`dpkg-deb` (есть в Debian/Crostini по умолчанию):

```bash
./packaging/build.sh
```

На выходе в `dist/`:

| Файл | Что это |
|---|---|
| `PenguinCraft-<версия>-installer.sh` | самораспаковывающийся установщик, без root |
| `penguincraft_<версия>_all.deb` | пакет для `apt` |

Оба варианта самодостаточны: они кладут исходники и иконку, создают
команду и пункт меню. Внешних зависимостей, кроме `python3-tk`, нет.

> **Почему не AppImage?** Приложению нужны системные Tcl/Tk и Python, а
> AppImage потребовал бы упаковывать их внутрь и работал бы только при
> наличии FUSE (`libfuse2`), что на Crostini капризно. Установщик и `.deb`
> используют системный Python — проще, меньше по размеру и надёжнее.

### Windows

PyInstaller не умеет кросс-компиляцию, поэтому `.exe` собирается **на
Windows**. Нужны Python 3.9+, `pyinstaller` и (для установщика) Inno Setup 6:

```powershell
python -m pip install pyinstaller
python packaging\windows\build.py              # .exe + установщик
python packaging\windows\build.py --portable-only   # только переносимый .exe
```

На выходе в `dist/`:

| Файл | Что это |
|---|---|
| `PenguinCraft-<версия>-portable.exe` | один файл, ничего не устанавливает |
| `PenguinCraft-<версия>-setup.exe` | установщик в профиль пользователя |

Сторонний пакет (PyInstaller) нужен **только при сборке** — сам лаунчер
по-прежнему обходится стандартной библиотекой. Иконка `.ico` делается
скриптом `packaging/windows/make_icon.py` из того же PNG-файла, что и в
Linux-сборке, без сторонних библиотек.

Всё это автоматически собирает workflow
`.github/workflows/windows.yml`; по тегу вида `v1.4.0` файлы `.exe`
прикладываются к релизу.

## Быстрый старт

1. Откройте вкладку **Аккаунты** и добавьте профиль: офлайн-ник,
   Microsoft (код устройства) или Ely.by.
2. Вкладка **Экземпляры** → **Создать**: выберите версию Minecraft,
   загрузчик (можно «Ванилла») и при желании сразу скачайте файлы.
3. Нажмите **Играть**. Если Java нужной версии нет — лаунчер сам её
   скачает с Adoptium.
4. Моды — во вкладке **Моды** (поиск в Modrinth), сборки — во вкладке
   **Модпаки**. Обязательные зависимости подтягиваются автоматически
   (галочка «Зависимости»), а кнопка «Проверить зависимости» подскажет,
   чего не хватает.
5. Если игра «не запускается непонятно почему» — кнопка **Проверить
   файлы** на странице экземпляра найдёт и докачает повреждённые файлы.

## Командная строка

```
penguincraft [--root КАТАЛОГ] [-v] КОМАНДА

  gui                     запустить графический интерфейс
  info                    состояние лаунчера
  doctor                  диагностика окружения
  versions                список версий Minecraft
  install ВЕРСИЯ          установить версию/загрузчик
  instances               список экземпляров
  create ИМЯ --version …  создать экземпляр
  launch ЭКЗЕМПЛЯР         запустить игру
  accounts                список аккаунтов
  account-add-offline НИК
  account-ms-login
  account-elyby ЛОГИН
  mod-search ЗАПРОС
  modpack-install ИСТОЧНИК
  verify ЭКЗЕМПЛЯР [--deep] [--repair]
  worlds ЭКЗЕМПЛЯР
  update-mods
  check-updates
```

Примеры:

```bash
# Установить Fabric 1.20.1 и создать экземпляр
penguincraft install 1.20.1 --loader fabric

# Поставить модпак из файла
penguincraft modpack-install ~/Downloads/SuperPack.mrpack

# Найти мод
penguincraft mod-search sodium --loader fabric --version 1.20.1

# Проверить файлы игры и починить повреждённые
penguincraft verify "Моя сборка" --deep --repair

# Обновить моды во всех экземплярах
penguincraft update-mods
```

## Каталог данных

По умолчанию — `~/.local/share/penguincraft` (Linux/ChromeOS) или
`%LOCALAPPDATA%\PenguinCraft` (Windows). Переопределяется переменной
`PENGUINCRAFT_HOME` или флагом `--root`.

```
<каталог данных>/
├── settings.json              настройки
├── accounts.json              аккаунты (права 600)
├── versions/                  описания и клиентские jar'ы версий
├── libraries/                 общие библиотеки (maven-раскладка)
├── assets/                    ресурсы игры
├── runtimes/                  автоматически скачанные JRE
├── logs/                      журналы запусков
└── instances/
    └── 1.20.1 Fabric/         «нужная версия», которую вы открываете
        ├── .minecraft/        домашний каталог игры
        │   ├── mods/          моды
        │   ├── config/        настройки модов
        │   ├── saves/         миры
        │   ├── resourcepacks/ ресурспаки
        │   ├── shaderpacks/   шейдеры
        │   ├── logs/          журналы самой игры
        │   └── options.txt
        └── instance.json      описание экземпляра (версия, загрузчик)
```

Экземпляр = один «домашний» каталог игры. Внутренний каталог называется
`.minecraft` намеренно: это **то самое имя, которое знает любой игрок** —
так называлась папка у официального лаунчера (`%APPDATA%\.minecraft`,
`~/.minecraft`), и так же делают Prism Launcher и MultiMC, отводя каждому
экземпляру собственный `.minecraft`. Поэтому моды, миры и настройки лежат
ровно там, где их ожидаешь найти.

В Linux `.minecraft` — скрытый каталог (как и обычный `~/.minecraft`):
включите показ скрытых файлов (`Ctrl+H` в файловом менеджере) или просто
нажмите **Открыть каталог** на странице «Экземпляры». В Windows каталог
виден как обычно.

> **Обновление с 1.3.0 и раньше.** Прежний каталог `game/` переносится в
> `.minecraft/` автоматически при первом запуске новой версии. Это
> переименование: моды, миры и настройки остаются на месте. Архивы
> экземпляров, сделанные старой версией, тоже импортируются.

## Профили JVM

| Профиль | Для кого |
|---|---|
| Хромбук (экономный) | 4 ГБ ОЗУ, 2 ядра — Serial GC, быстрый старт |
| Сбалансированный | 8 ГБ ОЗУ — G1GC с флагами Aikar |
| Производительность | 8–16 ГБ ОЗУ, тяжёлые сборки |
| Ванилла без модов | минимум лишнего |
| Свой набор | только указанные вами аргументы |

Память подбирается автоматически под объём ОЗУ, но её всегда можно
задать вручную в настройках экземпляра или лаунчера.

## Заметки для ChromeOS

- Установите Linux (Crostini), если ещё не включён, и выполните
  `sudo apt install python3 python3-tk`.
- Лаунчер не требует прав root и не пишет за пределы своего каталога.
- Для максимальной плавности включите профиль **Хромбук** и пресет
  графики **Хромбук** (уменьшает дальность прорисовки и частицы).
- Если драйверы работают нестабильно, попробуйте в настройках игры
  включить **Программный OpenGL**.

## Структура кода

```
penguincraft/
├── core/       сеть, версии, библиотеки, ресурсы, Java, запуск,
│               целостность файлов и проверка обновлений
├── auth/       аккаунты: Microsoft, офлайн, Ely.by
├── loaders/    Fabric, Quilt, Forge, NeoForge, ванилла
├── mods/       Modrinth, установка .mrpack, работа с mods/,
│               зависимости модов
├── ui/         tkinter-интерфейс (тема, виджеты, страницы, иконка)
├── manager.py  фасад для интерфейса и CLI
└── cli.py      командная строка

tests/          автотесты (unittest, без сети и графики)

packaging/
├── build.sh        сборка .deb и установщика в dist/ (Linux)
├── installer.sh.in шаблон самораспаковывающегося установщика
├── deb/            файлы пакета: control, postinst, postrm, copyright
└── windows/        сборка .exe: build.py, PyInstaller-обёртка,
                    скрипт Inno Setup, генератор иконки .ico
```

## Тесты

Автотесты не требуют сети и графики:

```bash
python3 -m unittest discover -s tests -t .
```

В репозитории есть два workflow GitHub Actions:

- `.github/workflows/ci.yml` — проверяет синтаксис, отсутствие сторонних
  импортов и прогоняет тесты на Python 3.9–3.13 (Linux);
- `.github/workflows/windows.yml` — те же тесты под Windows и сборка
  `.exe`/установщика.

Тесты можно запустить и на Windows:

```powershell
python -m unittest discover -s tests -t .
```
